# tikflowso 产品需求文档

版本 1.2 · 2026-11-20 · 面向产品、设计、数据、研发与验收团队

## 1. 产品目标与成功条件

tikflowso 帮助 TikTok Shop 卖家、达人运营和内容策划回答三个问题：哪个市场的哪些商品正在增长，谁在带动销售，哪些内容值得继续跟踪。用户从工作台进入榜单，收窄市场与时间范围，核对某个对象的表现，再把候选对象留给下一次运营决策。

**首发成功条件**：一名首次使用者应能在五分钟内找到某市场表现最好的商品、解释所选窗口的销售变化，并保存或导出可复查的候选名单。验收时记录完成时间、所用筛选条件及导出行数。上线后按周统计首次完成这一流程的工作区占比、产生第二次研究行为的工作区占比，以及按源约定时间到达的数据批次占比。样例访问与真实客户使用分别计量。

## 3. 用户与业务流程

| 角色 | 起点与关键选择 | 完成时应能交付 |
|---|---|---|
| 选品运营 | 选择市场和周期 → 查看商品销量或成交额 → 筛选类目 → 检查趋势与关联店铺 | 一份保持相同筛选、单位和排序的候选商品表 |
| 达人运营 | 选择达人榜 → 按成交或涨粉比较 → 查看带货内容 → 保存目标 | 可复查的达人名单及入选理由；有许可时才显示合作联系方式 |
| 内容策划 | 查看视频/直播榜 → 比较热销与高曝光内容 → 选定参考内容 → 整理选题 | 能定位参考素材、商品和市场的创作记录 |
| 数据运营 | 导入来源明确的日数据 → 检查成功或失败 → 回到榜单核对结果 | 可复现的输入、错误原因、更新日期和同口径统计 |
| 工作区管理员 | 管理成员、授权、套餐、访问凭据和用量 | 每个请求归属明确，账单变化有事件可追查 |

## 4. 功能范围与优先级

P0 为本地投用需要的研究闭环，P1 为完整分析与运营工作流，P2 为面向多客户运营的商业化范围。该表规定产品验收目标，实际完成度以代码、运行记录和交付说明为准。

| 编号 / 级别 | 模块与需求 | 验收场景 |
|---|---|---|
| F01 / P0 | 工作台以市场和周期统领指标、历史趋势、快捷入口和榜单摘要；标注数据性质及币种 | 切换市场或窗口后，所有摘要使用新条件；从摘要进入对应完整榜单 |
| F02 / P0 | 商品、店铺、达人、视频、直播均可查询、筛选、排序、查看详情；支持排行、搜索无结果、错误及空数据状态 | 已知数据中检索一个对象并核对数字；查询不存在的对象时给出可恢复的空状态 |
| F03 / P0–P1 | 商品按销量、成交额及推广热度研究；店铺细分本地/跨境/S 店；达人比较成交、净增粉和黑马；视频区分短视频与图文；直播按成交表现排序 | 分类字段与上游定义一致。差异化榜单使用各自的指标、筛选和名称；缺少某项指标时说明缺失 |
| F04 / P0–P1 | 详情提供基础档案、周期销量/GMV、逐日趋势。P1 增加商品—店铺—达人—视频/直播的明确关系、达人受众与里程碑、商品评价及直播流量 | 更改窗口后明细和趋势一致。关联对象可回查；缺失关系不会生成猜测链接 |
| F05 / P0 | 收藏候选对象、按当前条件导出表格；保留可识别的市场与指标单位 | 重启后收藏仍在；重复收藏不产生第二条；导出与列表同一查询且顺序一致 |
| F06 / P0 | 通过有来源的日快照向数据层写入，按业务键去重。样例可独立运行，真实源可逐批验证 | 导入同一批两次不会翻倍；一行坏数据导致整批失败或产生明确的逐行结果；失败不污染已发布统计 |
| F07 / P1 | 市场和类目看板提供规模、竞争、价格带与趋势；按市场、类目、时间钻取商品。市场分析只汇总同一事实粒度 | 汇总到具体对象，展示覆盖范围、可比较的币种和窗口；无价格时显示缺失 |
| F08 / P1 | 灵感库和趋势研究支持话题、音乐、关键词、热门脚本及代表内容 | 每条趋势有时间、市场及依据；无使用量时不生成流行度；灵感条目可保存复查 |
| F09 / P1 | 商品、视频、直播监控支持创建、生命周期、最近执行结果、退出监控；区分入库延迟与阈值触发 | 新快照触发已配置条件；重复处理同一批次只生成一次结果。直播实时分析须接入实时源 |
| F10 / P1 | 问答助手引用当前数据与窗口。工具覆盖创意、脚本、标题、邀约、图片文字处理与视频拆解 | 对无依据的问题显示数据缺口。生成与模板输出应标明方式；图片/视频结果须由实际媒体输入产生 |
| F11 / P1 | 费用计算器填写销售收入、货品成本、佣金和其他费用，允许用户覆盖假设；教程解释指标和操作 | 可用手算案例核对利润与利润率；缺少费率时可填写；显示所采用的币种与费率 |
| F12 / P2 | 注册/登录、团队成员、订阅、周期、配额、升级、退款和联盟归因；不同角色控制导出及联系人访问 | 跨工作区数据隔离；重复支付回调只生效一次；配额用尽提供明确状态；生产支付必须完成真实账户联调 |

| F14 / P2 | 联盟与授权素材工作流，包括归因、结算、素材下载和货盘管理；相应入口依赖单独授权 | 对有权使用的素材试运行并记录授权范围；结算单能追溯订单及退款。货盘业务含义需用客户样例确认 |

## 5. 数据对象与指标契约

五类分析对象共享稳定标识、名称、类型、市场、类目和来源。资料快照描述某日可见的对象属性，日事实描述该日活动，关联记录说明对象之间的关系及依据。工作区持有收藏、监控及使用记录。生产接口需携带来源、数据截止时间、统计口径版本与实际覆盖范围。

| 指标 | tikflowso 口径及边界 |
|---|---|
| 销量 | 窗口内各日售出件数之和。订单数、退款件数单独入库；来源只有累计量时先按同一对象相邻有效快照计算增量 |
| GMV | 对相同市场、币种、时间和对象粒度的日成交金额求和。平台估值保留“估算”标识。商品、店铺、达人、内容各自代表不同观察维度，跨维度相加会重复 |
| 增长 | 环比使用紧邻、等长的前一窗口，增长率为（本期值 − 前期值）÷ 前期值。无前期、分母为零或覆盖不完整时标为不可比；净增粉为期末与基期粉丝存量之差 |
| 粉丝与观看 | 粉丝是时点存量，周期内取期末有效值；视频播放、直播观看和在线峰值各自标注来源口径，只有日增量可跨日相加 |
| 均价与占比 | 成交均价按 GMV ÷ 销量计算。类目 GMV 占比的分母取相同市场、时间和币种下的商品 GMV；分母为零返回缺失 |
| 工作台总量 | 总成交额与成交件数只从商品日事实汇总。内容曝光来自视频播放和直播观看，须标注该指标按次数计量。活跃达人是窗口内有快照的去重达人。所有指标限定所选来源、市场和截止日 |
| 排名及时间 | 在当前筛选范围内按所选指标排序，相同数值用稳定标识打破并列；日期按该来源约定的统计日。跨市场视图首先明确时区及币种，跨币种原值不可直接求和 |
| 门店和内容标记 | 本地、跨境、S 店、图文、推广等作为源字段。黑马与热推若采用 tikflowso 自定义算法，须公布输入和最低样本条件，并标注算法版本 |

## 6. tikflowso 架构设计

首版采用浏览器原生 JavaScript、Python 标准库 HTTP 服务和 SQLite。单机可启动整条数据链，页面、查询和导出共用服务端统计结果。技术选型属于本项目决定。

| 层 | 职责与接口约束 |
|---|---|
| 展示 | 工作台、数据库、详情、收藏与工具通过同源 HTTP 访问服务。市场、日期和排序进入明确的查询状态；慢请求不能覆盖用户刚选择的新市场 |
| 应用 | 负责参数校验、搜索/排序/分页、详情、时间序列、工作区写操作及导出；同一指标在摘要与列表调用相同聚合逻辑 |
| 存储 | 对象和日期构成事实记录的业务键，以市场/类型/日期和对象/日期支撑检索。金额保留统一精度；标识作为文本存储；索引随真实数据量验证 |
| 入库 | 授权输入 → 解析 → 校验市场、对象、日期、指标和来源 → 单事务写入 → 可查统计。每次修订应可追溯；只有成功批次可进入监控计算 |
| 工作区 | 本地研究可采用单工作区。账户、角色、会话、工作区归属、来源访问检查和凭据管理用于多人部署；配额事件与受限操作关联 |
| 外部集成 | 数据授权方供给日快照；实时监控、生成模型、OCR/翻译、支付与消息服务独立接入。接口需声明密钥、成本、超时、重试及降级结果 |

**生产容量验收目标**：以十万条对象日记录建立可复现基准；在选定生产硬件和指定并发数下，目标是常用榜单 P95 低于一秒，超大导出进入后台任务。每日验证最近数据日期与批次行数，定期从备份恢复并比对对象数量和聚合值。本机容量抽样与一致备份校验已完成，生产硬件及异地恢复仍待验收。

## 8. 交付验收清单

1. **一致性**：准备含两个市场、三个日期和多种对象的固定数据；手工计算已知商品 GMV、销量、均价与排名；分别核对首页、列表、详情与导出。
2. **时间与缺失**：选择无数据市场、窗口超出覆盖范围、前期为零、同分对象和缺失关系；用户可区分零、无记录及不可比较。
3. **变更与持久化**：批量入库中故意加入错误日期，重试同一批次，再修订一天的值；验证事务、去重及汇总重算。收藏增删后重启验证。
4. **交互**：桌面和窄屏宽度操作核心流程；键盘可操作筛选和详情退出；慢请求、错误和空结果有状态反馈。
5. **外接能力**：逐个用测试凭据验证来源同步、模型、支付、通知和 API 配额，从输入到回执记录实际结果；测试通过前保持对应功能的配置状态可见。

**待业务方确认的决策**：首批真实市场及数据供应商、指标可披露范围、销售归因窗口及估算方式、历史授权长度、支付和模型服务商、商业套餐与服务等级。任何一项以真实运行依赖为条件的需求均须单独验收。

## 9. 开发者与支付接入验收

**开放平台。** 在工作区注册账户后创建访问密钥。CLI 读取环境变量 `TIKFLOWSO_API_KEY`，默认访问 `http://127.0.0.1:8765`，部署到其他地址时设置 `TIKFLOWSO_URL`。以下命令共用工作区身份、来源访问控制和月度 API 额度。

```sh
python3 cli.py meta
python3 cli.py rankings --kind products --market US --source demo --sort sales --days 7
python3 cli.py detail --kind products --id p01 --source demo --market US
python3 cli.py trends --group music --market US
python3 cli.py trend-study --group music --market US
```

**MCP。** 将客户端本机启动命令设为 `python3`，参数为 `/Users/caiwenbin/tikflowso/cli.py` 和 `mcp`，环境使用同一 API 密钥及工作区地址。迁移项目后应同步修改绝对路径。stdio 协议版本为 2025-06-18，工具目录包括 meta、markets、overview、rankings、detail、trends、trend-study。工作区所有密钥共享每分钟 60 次的上限。超过分钟或月度额度返回 HTTP 429，响应头 Retry-After 和正文 retry_after 给出恢复秒数。成功的分析请求计入月度 API 用量。[协议与传输](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)

**Chrome 扩展。** 在扩展管理页通过“加载已解压的扩展程序”选择项目的 `extension/`。用户点击扩展图标后读取当前标签页 URL，仅识别 TikTok 详情链接。商品 ID、达人 handle 或视频 ID 作为工作区搜索条件；已导入的数据才能命中。支持本机或 HTTPS 工作区，工作区地址保存在浏览器本地。无需授予持续读取浏览历史或网页正文的权限。

**支付。** 配置 `STRIPE_SECRET_KEY`、`STRIPE_WEBHOOK_SECRET`、`STRIPE_PRICE_PRO`、`STRIPE_PRICE_TEAM` 及 `TIKFLOWSO_PUBLIC_URL`。后两项价格 ID 应来自同一 Stripe 环境中不同的循环收费价格。启用 Stripe 客户门户，让工作区所有者管理付款方式、套餐与取消。将 `/api/billing/webhook` 注册为事件目的地，订阅 `checkout.session.completed`、`customer.subscription.*`、`invoice.paid`、`charge.succeeded`、`charge.refunded`、`refund.updated` 及 `charge.dispute.created/updated/closed` 三类争议事件。生产环境使用公网 HTTPS。套餐数额由这些已配置的价格决定。[Checkout](https://docs.stripe.com/api/checkout/sessions/create) · [客户门户](https://docs.stripe.com/api/customer_portal/sessions/create) · [回调说明](https://docs.stripe.com/webhooks)

服务端用签名、签名时间和本地客户映射校验通知，以支付平台当前的订阅状态核定权益。已生效或试用中的有效价格可获得付费权限。回放、乱序和并发回调必须保持工作区归属与权益一致。真实支付沙箱尚待配置，当前支付验证使用本地模拟响应。

**推荐与退款。** 推荐人生成个人推荐码，新用户在首次注册时主动同意绑定，绑定时按 `TIKFLOWSO_AFFILIATE_BPS` 锁定佣金基点，默认值为 0。若业务方约定 12.5%，应在接受该批注册前配置 1250。计佣基数为符合价格清单的订阅账单实际收取金额；部分或全部成功退款冲减累计净额。单笔应计佣金为净额乘以签约基点并向下取整到原最小货币单位。跨月退款记在退款所属 UTC 月，支持按发票、收款和退款 ID 逐项核对。沙盒与正式流水、不同币种各自汇总；建议为测试环境和生产环境使用独立数据库及支付密钥。合作方可按月提交结算快照，财务经办人通过本机管理命令审批并填写依据。实际转账由运营方执行。[发票付款记录](https://docs.stripe.com/api/invoice-payment/list) · [退款明细](https://docs.stripe.com/api/refunds/list)

### 容量和恢复实测

同机 HTTP 试验准备了 365 天、109,500 条商品日事实，另外建立了 60,000 个不同商品的导出样本。四个读客户端与一个写入端并发 30 秒，本轮复跑完成 762 次榜单请求、195 次写入提交，HTTP P95 为 345.9 毫秒。导出的 CSV 为 5,017,404 字节。将在线备份恢复至独立服务后，重新登录，全年汇总一致，重新下载的 CSV 逐字节一致。该结果描述本次本机负载。异地恢复、持续峰值和生产服务等级仍需在部署环境验收。
