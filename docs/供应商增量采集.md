# 用 dlt 接收授权供应商的商品日数据

此连接器适用于按修订时间查询、用游标翻页的 JSON API。每个配置绑定一个供应商来源、市场和币种。按天发布的文件沿用 TikFlowSo 的目录导入、工作区权限和修订记录。采集进程使用 dlt 的 RESTClient 与 JSONResponseCursorPaginator。[dlt 客户端](https://dlthub.com/docs/dlt-ecosystem/verified-sources/rest_api/client)

## 离线复验

在仓库根目录运行。安装依赖后，测试只访问本机临时 HTTP 服务和临时数据库。macOS 或 Linux 可直接使用下列命令。

```sh
python3.13 -m venv .data/dlt-venv
.data/dlt-venv/bin/python -m pip install -r connectors/dlt-requirements.txt
RUNTIME__DLTHUB_TELEMETRY=false TIKFLOWSO_ENV_FILE=/dev/null .data/dlt-venv/bin/python -m unittest -v qa.dlt_supplier_acceptance
```

测试把 14 天、每天两个商品的合成记录从模拟供应商送入真实导入器，逐日核对商品数、销量和本币 GMV。其他用例覆盖末页缺失、游标重复、迟到修订、时间戳异常、原生 JSON 金额精度、历史回补、删除标记、重复执行和写文件中断后的恢复。

## 供数契约

下例中的供应商按店铺的统计日期输出商品日销量和本币 GMV。修订时间 `updated_at` 独立于统计日，须带时区，最多保留六位小数。修订时间比采集开始时间晚五分钟以上时，整批会被拒收，以免后续数据被跳过。查询 `updated_since` **包含起点**，同一查询的游标应稳定覆盖全部修订，包括更新时间相同的多件商品。每次修订需给出完整商品日记录。同一来源、日期、商品 ID 和修订时间对应唯一的业务内容。相同金额的等值表示（如 `10.15` 和 `10.150`）可以重复交付。固定参数可约定店铺和其他非敏感范围。

```json
{
  "source": "ws-1-catalog",
  "url": "https://supplier.example.invalid/v1/product-days",
  "market": "US",
  "currency": "USD",
  "token_env": "SUPPLIER_BEARER_TOKEN",
  "initial_since": "2026-10-01T00:00:00Z",
  "params": {"shop": "authorized-shop"},
  "items_path": "page.rows",
  "cursor_path": "page.next",
  "total_path": "page.total",
  "lookback_seconds": 3600,
  "fields": {"id":"product.id","date":"day","name":"product.title","sales":"units","gmv":"amount"}
}
```

一个末页响应如下。中间页用非空字符串返回下一页游标。金额可用十进制字符串或 JSON 数字，需精确到分。商品 ID 建议用字符串保留前导零。产品名称、销量和 GMV 为必填。可将 `shop_id` 等日快照字段加入映射。当市场和币种来自嵌套字段时，在 `fields` 中配置 `market` 和 `currency` 的路径，以便逐条核对。

```json
{"page":{"rows":[{"product":{"id":"001","title":"示例商品"},"day":"2026-11-01","units":2,"amount":"10.15","market":"US","currency":"USD","updated_at":"2026-11-04T18:00:00Z"}],"next":null,"total":1}}
```

可设置 `since_param`、`cursor_param` 和 `updated_field` 来适配供应商命名。默认依次为 `updated_since`、`cursor`、`updated_at`。删除事件需由供应商明确处理。遇到顶层 `deleted: true` 会终止该批次并保留水位。若使用其他布尔删除字段，以 `deleted_field` 配置其路径。

当供应商在每页提供本次查询的**全量修订条数**时，可配置 `total_path`，例如上面的 `page.total`。采集器核对跨页总数是否稳定、每条修订是否唯一，以及末页时收到的条数是否一致。任何一项失败都会保留原水位。供应商只提供本页条数或总页数时，请省略此配置。此时，提前返回结束游标造成的缺页无法仅从响应识别。

`lookback_seconds` 是可选的非负整数，默认为 0。例中的 3600 会将下次查询起点向前移一小时，最早回到 `initial_since`。窗口内迟到的商品修订按该商品的最近版本处理，整体水位只会向前推进。更早的修订可用 `--backfill-from` 主动回读。已有采集目录可直接启用或调整这两项。

## 采集、修订和导入

将配置保存到本机，令牌由环境变量提供。`--out` 使用此供数配置专用的空目录。采集与导入进程需要共享该目录的读取权限。

```sh
.data/dlt-venv/bin/python -m connectors.dlt_supplier --config /absolute/path/supplier.json --out /absolute/path/drop
.data/dlt-venv/bin/python -m connectors.dlt_supplier --config /absolute/path/supplier.json --out /absolute/path/drop --backfill-from 2026-10-01T00:00:00Z
```

第一条命令同时用于首轮及后续增量采集。第二条按**修订时间**向前回读，保留当前最高水位和每条记录的最新版本。若该区间有日文件遗失，回补会从 SQLite 中恢复当日完整交付。采集器等所有页校验通过后，在本地 SQLite 一起提交数据、水位和待发布日期，再逐日原子替换 JSON。失败后用相同命令重跑。备份或迁移时请保留整个目录，包括隐藏的 SQLite 文件。每个统计日的交付文件上限为 32 MiB。

在 `feeds.json` 增加对应配置，下例把来源交给已注册的工作区 1。将 `directory` 与 `--out` 设为同一绝对路径，将 `source` 与采集配置设为同一 ID，然后运行一次导入或让现有定时导入接收文件。[目录导入与权限配置](数据接入.md#定时接收目录与-https-交付)

```json
[{"id":"catalog-drop","source":"ws-1-catalog","owner":1,"directory":"/absolute/path/drop"}]
```

```sh
python3 feeds.py --config /absolute/path/feeds.json --db /absolute/path/tikflowso.sqlite3
```
