# tikflowso 数据接入

## 从两条记录核对一张榜

以下样例用于验算。保存为 UTF-8 编码的 `daily.csv`，在项目目录运行导入命令，数据库路径应与正在使用的 tikflowso 服务一致。

```csv
market,kind,id,name,date,gmv,sales,price,category,shop_id
US,products,sku-17,随行笔记本,2026-11-18,20.00,2,10.00,文具办公,shop-3
US,products,sku-17,随行笔记本,2026-11-19,33.00,3,11.00,文具办公,shop-3
```

```sh
python3 analytics.py daily.csv --source partner --db /absolute/path/to/tikflowso.sqlite3
```

选择来源 `partner`、美国、截止日 11 月 19 日、两天窗口，SKU 的 GMV 为 53 美元，销量 5 件，成交均价 10.60 美元，最近标价 11 美元。选一天窗口后，GMV 为 33 美元，比前一天增长 65%。`shop-3` 的店铺记录入库后，详情页可跳转到对应店铺。

## 数据契约

每一行是一个来源、市场、对象类型、对象 ID、统计日的完整快照。相同业务键再次导入会整体替换当天记录，未提供的可选字段相应清空。批次中有重复键时，以最后一行为准。服务按来源给定的统计日汇总；供应商应在上游处理时区、退货口径、累计计数器重置、币种转换和销售归因，并确认关联对象的使用授权。

| 字段 | 含义与校验 |
|---|---|
| `market` | 必填。支持 US、GB、ID、MY、TH、VN、PH、SG、MX、BR、ES、FR、DE、IT、JP、IE。市场对应本币固定，例如 GB 为 GBP |
| `kind`、`id`、`name` | 必填。`kind` 枚举为 products、shops、creators、videos、lives。ID 最长 160 字符。保留文本 ID 里的前导零 |
| `date` | 必填。ISO 统计日 YYYY-MM-DD |
| `gmv`、`sales` | 必填。当天成交金额使用当地货币主单位，最多两位小数；销量为非负整数。销售缺失的记录须在供应端补齐或推迟导入 |
| `orders`、`refund_units` | 可选的当日订单数和退款件数，分别保存。该对象已入库的日记录中只要有一天缺失该字段，该窗口就不显示合计。显式零可以正常累计 |
| `gmv_estimated` | 可选的来源估算标识，接受 true、false、1、0。任一日标为估算时，对象及相关汇总提示含来源估算；未提供的标识保留为空 |
| `price` | 可选，当天标价，金额精度与 GMV 相同。成交均价另按 GMV 除以件数计算 |
| `views`、`followers`、`follower_growth` | 可选。观看为当日增量，粉丝为日末存量，净增粉可负。优先使用期末与基期存量差，缺乏基期时使用完整窗口的逐日净增量 |
| `subtitle`、`category`、`segment` | 可选，副标题、类目、来源分组。商品支持 promoted/new；店铺 local/crossborder/s；达人 rising/established；视频 video/image；直播 live/replay |
| `shop_id`、`creator_id`、`product_id` | 可选。指向同一来源和市场的对象 ID，允许先后到达。界面仅链接当前窗口存在的对象 |
| `tag`、`music`、`keyword`、`script` | 可选。单条内容当日的主话题、音乐、关键词及脚本类型。趋势统计按视频日记录的实际标注分组 |
| `image_key` | 可选。界面已收录的缩略图键；未识别时使用对象占位图 |
| `profile` | 可选。JSON 导入使用对象，CSV 使其成为经过标准 CSV 引号转义的 JSON 文本。每种扩展随当日快照保存 |

达人画像可包含 `{"audience":[{"name":"25–34 岁","share":42}],"milestones":[{"date":"2026-11-19","label":"突破五万粉丝"}]}`，占比采用百分数。商品评价例为 `{"reviews":[{"text":"包装完好","rating":4,"date":"2026-11-19"}]}`。直播流量例为 `{"live_traffic":{"peak_viewers":410,"avg_watch_seconds":54,"sources":[{"name":"推荐","share":70}]}}`。字段只用于已取得授权并能说明来源的资料。

管理页面支持上传 CSV 或 JSON 对象数组。浏览器导入会为来源加上当前工作区前缀。CLI 和定时接入使用给定的来源 ID，运维人员可指定 `ws-<工作区所有者数字ID>-<来源名>` 写入私有数据集，普通名称用于共享来源。内置 `demo` 来源仅含演示记录。

「使用资源 → 累计快照转日增量」接受同一来源内的完整对照文件。以 `cumulative_gmv`、`cumulative_sales` 代替日值，并带上首日之前的基线。工具按市场、类型、对象和日期排序，相同日期取文件最后一条。只对相邻统计日、两个计数器均未下降的记录取差，零增量保留。可以分别下载可导入日快照及跳过的明细。第一条、跨日缺口和计数器下降的当天只建立新基线。补交或修订历史累计值时，重新转换含其前一日和后一日的完整区间，再核对日快照修订记录。计数器重置的业务原因和来源时区由供数方解释。

「使用资源」按来源与市场显示最近快照日期和当天的记录数。当前工作区可回看最近 25 个上传批次；失败批次列出错误，写入行数为零。最近 25 条可见修订按业务键展示字段的原值和新值。修订审计从安装本版本起生效，已有历史的覆盖值无法追溯。

## 定时接收目录与 HTTPS 交付

配置文件示例。把路径、工作区 ID、域名和环境变量替换为已授权供应商的实际值。

```json
[
  {
    "id": "catalog-drop",
    "source": "ws-1-catalog",
    "directory": "/absolute/path/to/authorized-deliveries",
    "interval_seconds": 900
  },
  {
    "id": "licensed-daily",
    "source": "licensed-shared",
    "url": "https://supplier.example/daily/snapshots",
    "format": "json",
    "token_env": "SUPPLIER_BEARER_TOKEN",
    "interval_seconds": 3600
  }
]
```

在服务进程环境中将 `TIKFLOWSO_FEEDS` 指向此 JSON 文件，供应商令牌单独放入指定环境变量。每个来源选择目录或 URL 之一。URL 接受 HTTPS GET，支持同源 HTTPS 跳转，单次交付上限为 32 MiB。目录读取当前层级的 CSV/JSON 文件，按文件名排序，跳过隐藏文件。供应方可先写临时文件再原子重命名发布。

以下命令立即拉取并输出每个数据源的状态。没有到更新时间的计划任务会等待下一轮；强制拉取仍会比对内容散列。

已约定交付时间的 feed 可在该对象中追加 `"daily_delivery":{"markets":["US","GB"],"due_utc":"12:00","lag_days":1}`。这个例子表示每天 UTC 12:00 前交付前一统计日。计划首次被采集器读取后开始计时，修改约定后按新计划重新起算。「使用资源 → 交付时效」显示最近七个已到期日的准时数、应到数和每日期限。判断依据是对应市场、统计日首次成功入库的时间，之后的重放或修订不会重算首次到达时间。该指标衡量首次到达；完整行数与数据覆盖另行核对。

```sh
python3 feeds.py --config /absolute/path/to/feeds.json --db /absolute/path/to/tikflowso.sqlite3
```

每份交付独立成批。导入与该文件 SHA-256 检查点在同一事务提交；不变文件跳过，修订文件覆盖对应日快照。一份错误文件保留先前版本，其他可读文件可以继续处理；修复后重跑即可。移除交付文件不会删除历史记录，纠错应明确提交修订快照。每个 feed 使用有期限的数据库租约避免并发采集互相覆盖，进程异常退出后能恢复。运行状态写在 `feed_runs`，各文件最近成功检查点位于 `feed_items`。

## 跨市场、价格带和增长口径

`GET /api/markets?source=demo&date=2026-11-19&days=7` 以同一窗口列出各市场本币 GMV、销量、活跃商品/店铺/达人数、成交均价、具有商品快照的天数。省略日期时取该来源所有市场中的最新统计日，覆盖不足的市场仍然列出。金额只在单一市场内汇总。需要折算时，将 `TIKFLOWSO_FX_RATES` 设为受信任的本地汇率 JSON 文件路径。下列数字仅演示结构，表示 1 单位本币折合多少基础货币。

```json
{"base_currency":"USD","dates":{"2026-11-19":{"GBP":"1.25","MYR":"0.22"}}}
```

只采用与查询截止日相同的汇率；响应含汇率日期、汇率与折算 GMV。省略文件或缺少该日该币种时，折算金额为空，仍可查看本币原值。成交均价按 GMV ÷ 销量计算；价格带按窗口期内商品最近有效快照的标价划四分位，相同标价归为同组，缺价对象跳过。竞争集中度使用覆盖店铺的前三名 GMV 占全部被覆盖店铺 GMV 的比例。

黑马达人 v1 要求本期销售至少 20 件、期末粉丝低于 20 万、前期 GMV 为正且成交额环比增长至少 15%，两段窗口都须有完整逐日快照。增长缺少比较基准时返回空值。工作台总 GMV 和件数只使用商品，观看用视频与直播的日观看，活跃达人为有达人快照的去重对象数；不同粒度的成交不能相加。

## 验证范围

运行 `python3 -m unittest test_analytics test_feeds -v` 可以复核导入原子性、重复交付、修订与恢复、历史归属、净增粉、五类对象关系、黑马筛选、价格带及图文趋势结构，以及指定日汇率和市场覆盖。测试使用内存或临时 SQLite，远端下载使用受控替身；真实授权方需要独立验证供应 SLA、鉴权、历史回补和口径一致性。

本次在 arm64 工作机、Python 3.15 与 SQLite 3.54 上做了一次开发容量抽样。临时 WAL 数据库中为美国市场写入 75 日、1,350 对象的 101,250 条日事实；将内置样例的全部五类对象扩展 18 份，赋予独立对象 ID。每组先预热一次，再执行 20 次商品榜单查询，按升序的第 19 个样本取 P95，每次查询使用独立连接，计时范围为 `analytics.handle` 调用。

| 并发读连接数 | 7 日窗口 P95 | 30 日窗口 P95 |
|---:|---:|---:|
| 1 | 82.6 毫秒 | 181.0 毫秒 |
| 4 | 235.3 毫秒 | 584.3 毫秒 |

结果只代表此次本机暖缓存读取；网络、HTTP 序列化、写入竞争、长时间运行、真实数据分布、跨区恢复和生产硬件仍待上线验收。完整生产数据量应另行验证多窗口、并发导出和采集任务重叠时的行为。
