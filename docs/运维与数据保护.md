# 1.4 部署与数据保护

## 从 1.3.1 升级

在解包目录运行 `python3 deploy.py upgrade --home /部署实例`。构建时锁定了 Linux ARM64 和 AMD64 的 Python 包哈希及 SQLite 3.54.1。完整平台 wheel 缓存可通过 `TIKFLOWSO_WHEELHOUSE` 提供。安装以同一份锁文件逐包验签摘要。部署会在无外网的候选容器中运行发布包的所有单测，随后短暂停写，备份最后一次提交并启动新版本。检查 `/health` 和后台「运行与审计」。

旧数据来源中，`demo` 对访客可见，`ws-数字-名称` 归原工作区。其余旧来源保留数据并暂停展示。新来源即使带有工作区前缀，也须显式指定已注册所有者才能对其开放。根据授权合同执行下面的命令，定时供数文件也应使用相同的 owner 或 shared 配置。

```sh
python3 manage.py source-access --db /部署实例/data/tikflowso.sqlite3 --source 来源名 --owner 12
python3 manage.py source-access --db /部署实例/data/tikflowso.sqlite3 --source 来源名 --hold
```

受限级别覆盖列表、导出下载、对话、告警和回收站。旧版本曾公开的文件可能已有下载副本，请由供数方和部署方核对历史授权。

## 管理员交接与失窃处置

首次绑定同时显示验证器密钥与八个一次性恢复码。动态码按 30 秒计时，使用过的时间步和恢复码不可重复。1.3.1 的旧管理员会话在升级后失效。部署方应先核对交接对象身份，将生成的私有凭据文件经已确认的渠道交给本人，再由本人保存到凭据管理器。

```sh
python3 manage.py recover-admin --db /部署实例/data/tikflowso.sqlite3 --email 账户邮箱 --out /私有目录/新验证器.json
python3 manage.py grant-admin --db /部署实例/data/tikflowso.sqlite3 --email 账户邮箱 --proof-file /私有目录/十分钟交接码 --out /私有目录/管理员绑定.json
python3 manage.py revoke-sessions --db /部署实例/data/tikflowso.sqlite3 --email 账户邮箱
python3 manage.py issue-reset --db /部署实例/data/tikflowso.sqlite3 --email 账户邮箱 --out /私有目录/找回.json
```

交接码由接收账户本人在账户页生成。找回凭证限十五分钟、使用一次。在账户页的「找回密码」设置新密码。失窃设备还应从主机、代码仓库、支付平台和模型供应商撤销访问，轮换该设备接触过的凭据。由部署方记录核实人、时间和下次访问复核日期。

## 加密备份与时间点恢复

`deploy.py` 将恢复私钥放在实例的 `recovery/private.pem`，容器挂载其公钥。备份使用 OpenSSL CMS、RSA 与 AES-256-GCM。每天按 UTC 日期保留一个自动副本，约三十天后清理最早的日副本。手动副本和升级前副本由保管方管理。旧快照可用 `python3 deploy.py encrypt-backups --home /部署实例` 在原路径转换。程序先解密新副本，逐文件与原始字节核对，持久化密文后才清理原表示。在线数据库和供应商配置应放在加密磁盘。

```sh
python3 deploy.py upgrade --home /部署实例 --backup-dir /已挂载的异地备份卷/本站目录
python3 deploy.py restore /异地备份/备份目录 --restore-key /保管目录/private.pem --erasure-journal /保管目录/erasures.sqlite3 --home /隔离恢复实例 --port 8766
python3 deploy.py rollback --home /部署实例 --to /独立回退实例 --port 8767 --public-url http://127.0.0.1:8767
```

回退命令使用上次升级的镜像与停写快照，在新端口启动；正在服务的实例保留后续写入。健康检查、原币财务合计和实际业务读写通过后，由运维选择切流时间并处理快照后的差异。部署里首次发生账户注销才会创建登记簿。保管方应维护它的最新独立副本。恢复命令会重放私钥同目录的登记簿，放在别处时显式传入对应路径。

需要恢复到两个日备份之间时，先在部署所在 Docker 引擎上为 SQLite 启用连续复制。下列目录需事先挂载为独立加密文件系统，专供此实例使用。连续副本使用 Litestream，自身没有启用客户端文件加密，容器只访问本机挂载卷。副本不包含 service.env 和模型配置，恢复时应配套使用加密部署备份。按秒级同步边界恢复的最晚时间取决于最近成功复制的提交。

```sh
python3 replica.py start --home /部署实例 --replica-dir /已挂载加密卷/本实例
python3 replica.py restore --home /部署实例 --replica-dir /已挂载加密卷/本实例 --at 2026-11-20T08:30:00Z --out /隔离目录/recovered.sqlite3
python3 replica.py stop --home /部署实例
```

正常升级会暂停连续复制并在健康检查通过后恢复。整库回退后复制保持暂停，为新时间线指定新的副本目录。定期从独立主机演练恢复并记录实际恢复时间、可接受数据损失和负责人员。[Litestream 恢复参数](https://litestream.io/reference/restore/) · [SQLite 日志修复说明](https://sqlite.org/wal.html#the_wal_reset_bug)

## 模型出站与预算

工作区所有者在账户页为来源、端点与模型授权，并选择评论和历史。实际媒体工具会发送选定素材，请核对供应商地区及供数条款。无外发授权或云端研究不可用时，研究助手继续执行本地查询。纯云端任务会显示具体的配置或权限错误。

在实例的 `data/model-pricing.json` 建立价格与上限，令 `service.env` 中的 `TIKFLOWSO_MODEL_PRICING=/app/.data/model-pricing.json`。下面的金额为配置示例。用商户合同中可计费输入、缓存、推理、图片和输出的上界填写。缺少适配价格的端点会停止付费调用。

```json
{
  "platform_month_usd": "100",
  "workspace_month_usd": "10",
  "workspace_limits": {"12": "15"},
  "models": [{
    "endpoint": "https://provider.example/v1/chat/completions",
    "model": "contract-model",
    "context_tokens": 8192,
    "max_output_tokens": 1024,
    "input_usd_per_million": "1.00",
    "output_usd_per_million": "3.00",
    "fixed_usd": "0.00"
  }]
}
```

预算按 UTC 月份累计，以百万分之一美元记录。每个供应商子请求先预留上限，有可核实用量后按价格结算。未返回用量的请求保留预留。后台显示已计支出和未结请求，实际金额应与供应商账单核对。本机环回模型只有在运维显式开启 `TIKFLOWSO_TRUST_LOCAL_MODEL=1` 时才免预留与外发授权，适用于已核实离线运行的模型。

## 财务对账与投递

平台按发票付款分配逐笔入账。全额和部分退款按稳定的付款分配编号顺序摊回，正式使用前请合作方确认该规则。签名有效的回调先持久登记。失败记录按退避间隔重试，可从后台重新投递。对账命令仅向 Stripe 发起查询。默认输出本地差额，显式 `--apply` 才补写分录。历史已结算月份的差异由财务人员书面处理。

```sh
python3 manage.py reconcile-commissions --db /部署实例/data/tikflowso.sqlite3 --since 2026-10-01 --until 2026-11-01
```

配置商户地域、产品税务及登记后，可令 `STRIPE_AUTOMATIC_TAX=1` 在新的 Checkout 中启用自动计税。Stripe 催款、发票邮件、税务登记与实际费率需在商户侧验证。自动降级会释放团队席位与尚未领取的邀请。

邮件网关可将最终退信或投诉转为 `POST /api/notifications/feedback`。JSON 字段为 `event`、UTC 秒时间戳 `timestamp`、原邮件 `message_id` 和 `status`（`bounced` 或 `complained`）。以 `TIKFLOWSO_ALERT_FEEDBACK_SECRET` 对原始请求体做 HMAC-SHA256，将十六进制结果放入 `X-Notification-Signature`。只接受五分钟内的签名回执，同一事件去重；投诉会停用该工作区邮件。域名认证、退信转发和实际送达由邮件服务商验证。

## 隐私、运维与发布记录

部署方应通过资源中心的私密工单核实注销申请，先完成订阅、团队和最后一名管理员交接，再执行 `python3 manage.py erase-user --db /部署实例/data/tikflowso.sqlite3 --email 账户邮箱 --journal /部署实例/recovery/erasures.sqlite3`。本地身份、会话、私聊、支持请求和个人工作区数据会清理。财务凭据保留去实名化的数字主体，支付服务商和独立保存的副本需要单独处理。恢复旧副本时对同一编号和身份摘要重放。供数任务停止向已注销的工作区导入后再继续日常同步。

在 `service.env` 设置 `TIKFLOWSO_CHAT_RETENTION_DAYS`、`TIKFLOWSO_SUPPORT_RETENTION_DAYS` 和 `TIKFLOWSO_REVISION_RETENTION_DAYS`。默认零表示保持业务记录，避免升级时丢失旧数据。设定素材到期宽限天数 `TIKFLOWSO_ASSET_GRACE_DAYS` 后才清除到期附件字节；到期即停止下载。无法确认内容安全的附件只限上传者读取，指定的扫描器按退出码 0、1、其他分别报告通过、拒绝、运行错误。

外部探活应在独立故障域检查公开 HTTPS 的 `/health`。运维后台提供吞吐、延迟、异常组、失败队列及请求编号。管理员可重试失败导出、通知和账单事件。检查加密备份的时间并向实际值班人发送告警。部署方需登记域名、证书、发信域、供应商、值班联系人及持有人，在事故后记录影响、恢复时间和后续负责人。

GitHub 的验证工作流在推送、合并请求及每周计划中运行候选镜像测试和 Python 依赖审查。每次放行前应复核依赖告警、兼容性、支付协议和双语模型样例。项目内的回归无法代替商户沙箱、独立安全审查、无障碍验收、组织合规或生产 SLA。
